# 残る課題

実装はメッセージ API に統一しました。削除した API と静的構成は [API の一本化](API_CONSOLIDATION.md)、
現在の再実行手順は [テスト](TESTING.md) にまとめています。
整理前の設計・検証結果は [初期版の検証記録](archive/INITIAL_MILESTONE.md) に保存しています。

## 今回の整理後に必要な確認

- Windows／Linux の新しい CI 結果。ローカルでは Miri 両借用モデルに成功していますが、CI の固定ツールチェーンでも確認します。
- 制限のない環境での TCP・junction の試験と、依存パッケージを取得した後の Tauri 本体の検証。
- Rust 1.95 でのコアの最小バージョン検査。Bevy サンプルは 1.97.1 以上を要求します。
- Linux の実ウィンドウと GUI 操作。描画なしのバックエンド試験とは分けて確認します。

今回の変更に対する確認状況は、実際のローカル出力と新しい CI の結果を基準にします。
整理前の CI 成功を、今回の差分の確認済み結果には含めません。

## アプリケーション側で設計すること

サービス・要求・チェックポイントのスキーマ、外部 I/O の冪等性、資源移行の排他・rollback・復旧、
停止待ちの期限、未登録の独自処理の終了確認はアプリケーションが決めます。
登録処理の契約は [子処理とコールバック](MANAGED_ACTIVITIES.md)、
確定フックを使う移行は [ホスト資源・DB の移行](HOST_RESOURCE_MIGRATION.md) を参照してください。

## 初期版の対象外

本番配信、クラッシュ隔離、任意 Future のスタック移送、外部副作用の自動巻き戻し、
終了しない処理の強制停止、独自 spawn の自動発見、実行中 DLL の物理アンロードは提供しません。
DLL 保持は開発プロセスの再起動で区切り、終了後の管理コピーは明示的に掃除します。

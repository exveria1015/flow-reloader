# 開発時の運用

初期版は、同じ SDK の契約を守るローカルの信頼済み Rust ロジックを更新する用途です。
本番配信、クラッシュ隔離、外部副作用の自動切り戻しは提供しません。

## ビルドと切り替え

監視とビルドの方針はホストが決めます。`RequestRouter` 自体は Cargo やソース監視を起動しません。
`service_host` は同期ビルド、Tauri サンプルは子プロセスでバックグラウンドビルドを行います。
旧 `main!` の「Debug で監視、Release で静的 hot_run」という動作を、メッセージ API 全体の仕様と混同しないでください。

ビルド完了後に `unsafe prepare(path)` で候補をロード・検査し、`activate` で Drain、
または `restart` で登録ワーカーの停止・移行・再生成を行います。
候補の準備では共有資源の変更や外部送信を始めません。DLL の初期化コードにも同じ契約を要求します。

Drain 中に共存するコードが使えるサービス契約を維持してください。
ABI・サービス・状態スキーマの検査は、バイト列の意味や DLL の安全性の証明ではありません。
ABI を変えた場合はホストとロジックを両方再ビルドします。

## 失敗からの復旧

| 状況 | 挙動と対処 |
| --- | --- |
| ビルド・候補検査の失敗 | 旧受付と既存処理を維持。エラーを表示して候補を修正 |
| 古い候補・別 Router の候補 | 対象 Router の現在世代から準備し直す |
| Restart の終了待ち | 外部所有タスクの poll を進める。必要ならホスト側で期限を設定 |
| 受付停止後の移行失敗・Restart Future の Drop | 受付停止と旧チェックポイントを維持。再試行、または復旧方針を決めて `resume()?` |
| ロード予算枯渇 | ロードを止め、開発プロセスを再起動 |

`resume` は旧ワーカーを再生成したり I/O を取り消したりしません。通常リクエストの自動再実行もありません。
poll から戻らない処理は、同じスレッドの timeout では安全に強制停止できません。
詳しくは [Restart と移行](RESTART_AND_MIGRATION.md) を参照してください。

## 上限と観測

受付・ワーカーの世代、受付状態、管理対象の実行数、ビルド／ロードエラー、停止待ち、
チェックポイントサイズ、予算使用数、コピー先を記録します。
`in_flight()` は管理外タスク・外部コールバック・ロード済み DLL の数ではありません。

Router を作り直す場合も同じ `GenerationBudget` を共有すると、その開発セッションの累積枠を維持できます。
既定32枠は失敗・破棄候補を含むロード試行数であり、プロセス全体のメモリ上限ではありません。
チェックポイントは既定1ワーカーあたり1 MiB。入力・送信キューや I/O の上限はホストで別に設けます。

既定の KeepLoaded では DLL とコピーが蓄積します。コピー先はユーザー一時領域の `flow-reloader/<PID>/` です。
終了後も残る場合があるため、削除は対応プロセスの終了確認後に行ってください。
メッセージ API には自動アンロードがありません。旧 FlowRunner の unsafe 回収にも追加の終了確認が必要です。
[DLL の寿命と管理外タスク](UNLOAD_SAFETY.md) を参照してください。

サンプルで使用する `internal` のビルド・パス補助は非公開扱いの実装ユーティリティです。
アプリケーションでは独自のビルド手順から完成済み成果物を渡すこともできます。

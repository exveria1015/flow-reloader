## 現在提供するものと境界

- `RequestRouter` の Drain と、登録ワーカーの協調 Restart・チェックポイント移行。
- 明示登録した子 Future／外部処理の停止・join と、Drop 済みルートの所有スレッド上の終了待ち。
- 共有 `GenerationBudget` による累積ロード試行数上限と、ワーカーごとのチェックポイントサイズ上限。
- ホスト資源の版付き ID・バッファ API。操作は短い同期処理で、ネットワーク等はホストが所有。
- 所有するホスト Future の非同期呼び出し、キャンセルの終了応答待ち、複数ロジック所有スレッドからの有界 I/O キュー利用。
- 追加サービス要求の一括検査と明示割り当て、スキーマと codec で検証した世代ごとの初期化データ。
- 全ワーカー準備後のホスト確定フックと、SQLite・ホスト内キャッシュの移行／遮断／明示復旧の例。
- ネイティブ参照・コピー量の観測と、セッション排他で保護した新形式コピーの明示的な掃除。
- `Execution<S>` と旧 API の独立した Future 所有・同期的キャンセル。
- 実行・Waker による DLL 世代保持。KeepLoaded は管理外タスクの停止や借用先の寿命を保証しない。

終了しない処理の強制停止、Future スタックの移動、I/O の自動ロールバック、通常要求の自動再実行は提供しません。
生成マクロ付き DLL の自動回収で予算枠を再利用する機能もありません。
これらを今回の整理で「残ったバグ」と取り違えて実装を急ぐことはしません。

## 解決済みの安全性指摘

スナップショット状態の手書き自己参照、TLS の単一 Future slot、Release main の Pending 中の再借用は置き換えました。
`with_context*` はすべて unsafe に限定し、安全な main! の context 形式を削除しました。
新規の継続的ホストアクセスは版付きサービスで行います。旧コンテキスト API を安全な型付き API にしたわけではありません。

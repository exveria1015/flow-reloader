# Examples / サンプル一覧

Run commands from the workspace root. 新規実装では上段のメッセージ API の例を使ってください。

## Message API / 推奨する入口

| Command | What it demonstrates / 確認するもの |
| --- | --- |
| `cargo run -p service_host` | Host-owned TCP connection and Drain at message boundaries / 同じ接続の次の要求を新世代へ |
| `cargo run -p flow_reload --example restart` | Static worker shutdown, checkpoint schema migration, shared load budget / 停止・移行の最小例 |
| `cargo run -p tauri_tokio` | Native DLL builds, in-window editor, Drain/Restart, counter and build failure recovery / GUI で編集・復旧 |

- [service_host](service_host/src/main.rs) + [service_logic](service_logic/src/lib.rs):
  one client on `127.0.0.1:4000` (`FLOW_RELOAD_ADDR` overrides it). Send newline-terminated
  messages; `slow` takes about five seconds. Source edits trigger synchronous builds,
  processed at message boundaries or while polling a request. Not a general async server.
- [restart](../flow_reload/examples/restart.rs): statically linked APIs; native loading
  is covered separately by tests. [移行の説明](../docs_ja/RESTART_AND_MIGRATION.md)。
- [Tauri guide](../docs/TAURI_GUI_LAB.md) / [日本語](../docs_ja/TAURI_GUI_LAB.md): the historical package name `tauri_tokio`
  does not imply use of the old attached Tokio bridge. `tauri_tokio/dist/` contains
  **handwritten UI source**, embedded by Tauri; it is not disposable build output.
  `src-tauri/gen/schemas/` is generated by `tauri-build` and ignored.

## Compatibility API / 旧 API の検証例

These use `FlowRunner`, fixed `AppState` and ABI v4. They remain useful coverage
for supported APIs, but do not demonstrate message admission or Restart.

| Command | Logic crate | Role |
| --- | --- | --- |
| `cargo run -p sync_host` | `sync_logic` | Direct mutation and a copied `u64` init context |
| `cargo run -p snapshot_host` | `snapshot_logic` | Serde cartridge save/restore |
| `cargo run -p async_tokio_host` | `async_tokio_logic` | Scoped Tokio attached callbacks |
| `cargo run -p async_std_host` | `async_std_logic` | Scoped async-std attached callbacks |
| `cargo run -p async_smol_host` | `async_smol_logic` | Scoped smol attached callbacks |

These hosts build logic at startup and watch the resulting library, not the source.
After editing, build the corresponding logic crate into the same directory, e.g.:

```sh
cargo build -p async_tokio_logic --lib --target-dir examples/async_tokio_logic/target/hot-reload-build
```

`LOGIC_LIB_PATH` overrides the library path for these compatibility hosts.
The three attached hosts each run an echo server on `127.0.0.1:4001`; run them
one at a time. Similar logic is intentional: each host exercises a different runtime
adapter. For a source-watching compatibility host, `main!` has its own Debug-only
build loop; Release uses static `hot_run` instead. See the [API reference](../docs/API_REFERENCE.md).

## Test fixtures / テスト専用

[flow_reload/tests/fixtures](../flow_reload/tests/fixtures) contains standalone
`rustc` DLL sources for independent ABI and lifecycle checks. They are not runnable
application templates and deliberately do not use the proc macros.
See [testing](../docs/TESTING.md) for their role and commands.
